# Transponder Simulator

## Общее описание и общий принцип работы

`Transponder Simulator` имитирует автомобильный навигационный передатчик. Он читает маршрут из JSON-файла, последовательно превращает точки в события `VehiclePositionUpdated` и через заданный промежуток отправляет их в `Location Service`. Если `TARGET_URL` пуст, события выводятся в стандартный поток вместо HTTP.

Порядок работы:

1. `appconfig.Load` переносит несекретные параметры `config.yaml` в переменные окружения, не перезаписывая уже заданные значения.
2. `LoadConfig` читает и проверяет обязательные идентификаторы и числовые настройки.
3. `LoadRoute` читает JSON и проверяет координаты, скорость и точность каждой точки.
4. `Runner.Run` обходит маршрут, создает возрастающий номер последовательности и событие телеметрии.
5. `HTTPSender.Send` печатает JSON либо отправляет его HTTP-запросом с повторами.
6. После последней точки маршрут начинается заново, если `LOOP_ROUTE=true`.
7. `SIGINT` или `SIGTERM` отменяет контекст и завершает цикл без ошибки.

Отдельной базы данных и слоя `service` у симулятора нет. Все состояние находится в конфигурации, загруженном маршруте и памяти процесса.

## Модели

### `Config`

| Поле | Тип Go | Назначение |
|---|---|---|
| `VehicleID` | `string` | Обязательный идентификатор транспорта. |
| `BrigadeID` | `string` | Обязательный идентификатор бригады. |
| `DeviceID` | `string` | Идентификатор устройства; по умолчанию `simulator-<VehicleID>`. |
| `TargetURL` | `string` | Адрес приема телеметрии; пустое значение включает вывод JSON. |
| `APIKey` | `string` | Необязательный ключ заголовка `X-Transponder-Key`. |
| `RouteFile` | `string` | Файл маршрута; по умолчанию `routes/moscow-center.json`. |
| `Interval` | `time.Duration` | Задержка между точками; по умолчанию 2 секунды. |
| `RequestTimeout` | `time.Duration` | Тайм-аут HTTP; по умолчанию 5 секунд. |
| `RetryCount` | `int` | Число повторов после первой попытки; по умолчанию 3. |
| `LoopRoute` | `bool` | Нужно ли повторять маршрут; по умолчанию `true`. |
| `DefaultSpeed` | `float64` | Скорость, если она не задана в точке; по умолчанию 35 км/ч. |
| `AccuracyMeters` | `float64` | Точность, если она не задана в точке; по умолчанию 5 метров. |

### `Point` и `Route`

| Структура | Поле | Тип Go | Назначение |
|---|---|---|---|
| `Point` | `Latitude` | `float64` | Широта от -90 до 90. |
| `Point` | `Longitude` | `float64` | Долгота от -180 до 180. |
| `Point` | `SpeedKMH` | `*float64` | Необязательная неотрицательная скорость. |
| `Point` | `Accuracy` | `*float64` | Необязательная неотрицательная точность. |
| `Route` | `Name` | `string` | Название маршрута. |
| `Route` | `Points` | `[]Point` | Непустая последовательность точек. |

### `Event` и `Position`

| Структура | Поле | Тип Go | Назначение |
|---|---|---|---|
| `Event` | `EventID` | `string` | Случайный UUID события. |
| `Event` | `EventType` | `string` | Постоянное значение `VehiclePositionUpdated`. |
| `Event` | `EventVersion` | `int` | Версия формата, сейчас `1`. |
| `Event` | `OccurredAt` | `time.Time` | Время точки в UTC. |
| `Event` | `Payload` | `Position` | Данные положения. |
| `Position` | `DeviceID`, `VehicleID`, `BrigadeID` | `string` | Устройство, транспорт и бригада. |
| `Position` | `Sequence` | `uint64` | Возрастающий номер позиции. |
| `Position` | `Latitude`, `Longitude` | `float64` | Координаты. |
| `Position` | `SpeedKMH` | `float64` | Скорость в км/ч. |
| `Position` | `Heading` | `float64` | Направление движения в градусах от 0 до 360. |
| `Position` | `AccuracyMeters` | `float64` | Точность координаты в метрах. |
| `Position` | `Simulated` | `bool` | Всегда `true`, так как данные созданы симулятором. |

### `Runner` и `HTTPSender`

`Runner` хранит `cfg`, `route`, реализацию `Sender` и журнал. `HTTPSender` хранит адрес, ключ, число повторов, HTTP-клиент, поток вывода и начальную задержку повторной попытки.

## Функции

### `main`

Загружает конфигурацию и маршрут, создает отправителя и исполнитель, подписывается на `SIGINT`/`SIGTERM` и запускает `Runner.Run`. Ошибка любого обязательного этапа завершает процесс через `log.Fatalf`.

### `appconfig.Load`

Читает путь из `CONFIG_FILE` или использует `config.yaml`. Отсутствие файла допустимо. Найденные настройки передает `flatten`.

### `flatten`

Рекурсивно превращает вложенные ключи YAML в имена переменных окружения. Запрещает секретоподобные ключи, не перезаписывает существующие переменные, массивы объединяет запятыми.

### `LoadConfig`

Читает переменные окружения, подставляет значения по умолчанию и требует `VEHICLE_ID` и `BRIGADE_ID`. Проверяет положительные интервалы и тайм-аут, неотрицательные число повторов, скорость и точность.

### `envOrDefault`, `durationEnv`, `intEnv`, `floatEnv`, `boolEnv`

Читают строковое, временное, целое, вещественное и логическое значение. Пустое или неразбираемое значение заменяется переданным запасным значением.

### `Config.String`

Возвращает краткое безопасное описание конфигурации для журнала. Ключ API не включает; вместо пустого адреса пишет `stdout`.

### `LoadRoute`

Читает файл, разбирает JSON в `Route`, вызывает `Validate` и добавляет путь файла в каждую ошибку.

### `Route.Validate`

Требует хотя бы одну точку и последовательно проверяет диапазоны координат, неотрицательную скорость и точность. В ошибке указывает индекс точки.

### `NewRunner`

Сохраняет конфигурацию, маршрут, отправителя и журнал в `Runner`.

### `Runner.Run`

Начинает последовательность с текущего времени в наносекундах. Для каждой точки выбирает следующую, создает номер больше предыдущего, строит событие, отправляет его, записывает координаты и ждет `Interval`. Ошибка отправки останавливает весь запуск; отмена контекста считается штатным завершением.

### `wait`

Ждет таймер или отмену контекста и обязательно останавливает таймер при выходе.

### `NewSender`

Создает `HTTPSender` с тайм-аутом из конфигурации, стандартным выводом и начальной задержкой повторов 250 мс.

### `HTTPSender.Send`

Сериализует событие в JSON. При пустом адресе печатает одну строку. Иначе вызывает `sendOnce` до `RetryCount+1` раз; задержка удваивается, но показатель степени ограничен пятью. Отмена контекста прерывает ожидание.

### `HTTPSender.sendOnce`

Создает `POST` с контекстом, ставит `Content-Type`, `User-Agent` и при наличии ключа `X-Transponder-Key`. Полностью закрывает тело ответа. Успехом считает только коды 200–299.

### `NewEvent`

Выбирает скорость и точность точки либо значения конфигурации, создает UUID, время UTC и `Position`. Направление вычисляет от текущей точки к следующей.

### `heading`

Вычисляет начальный азимут по сферической формуле и нормализует его в диапазон `[0, 360)`. Для одинаковых точек возвращает ноль.

### `newUUID`

Получает 16 случайных байт, выставляет биты UUID версии 4 и формирует строку. Если источник случайности недоступен, возвращает шестнадцатеричное представление текущего времени.

## Структура БД

Симулятор не подключается к базе данных, не содержит SQL-миграций и ничего не сохраняет между запусками.

## Пример маршрута

```json
{
  "name": "demo",
  "points": [
    {"latitude": 55.7558, "longitude": 37.6173, "speed_kmh": 20},
    {"latitude": 55.7564, "longitude": 37.6191, "speed_kmh": 35}
  ]
}
```
