# Клиентское приложение (Frontend)

## Ответственность

Ролевой веб-интерфейс для жителя, работника, диспетчера и администратора.

## Ключевое поведение

- Роль после входа берётся из `GET /auth/me`; клиентское меню не заменяет
  серверную авторизацию.
- Маршруты `/verify-email` и `/reset-password` принимают одноразовый токен из
  ссылки Auth Service и выполняют соответствующие API-вызовы.
- Поддерживает веб-уведомления FCM через регистрацию устройства и Service Worker.
- Playwright покрывает вход, роли, заявки, профиль, администрирование, SLA,
  аудит, аналитику, отчёты и контракты API для чтения.
- Карта показывает заявки, транспорт и активный маршрут; серверные маршруты
  frontend также обращаются к Nominatim, Overpass API и Valhalla.

## Зависимости

| Категория | Текущая реализация |
|---|---|
| Хранилища / внешние системы | Состояние браузера; предметные данные поступают через API. Двоичная загрузка может идти напрямую в S3 по предварительно подписанному URL. |
| Синхронные взаимодействия | API Gateway; серверные маршруты также используют Nominatim, Overpass API и Valhalla. |
| Kafka | Frontend не является клиентом Kafka. |

## Эксплуатационная интерпретация

Страница описывает реализованные границы frontend в текущей ветке. Наличие
маршрута или настройки само по себе не считается доказательством полностью
работающего сквозного сценария.
